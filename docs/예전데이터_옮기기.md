# 예전 데이터(MariaDB) 옮기기

예전 버전(서버가 MariaDB에 저장하던 때)의 반·학생·출석 기록을 지금 출석 관리 프로그램으로 옮기는 도구입니다.
예전 DB는 읽기만 하고 바꾸지 않습니다.

## 다른 PC에서 쓰는 법
1. `dist_tools\AttendanceMigrate.exe` 파일 하나를 그 PC로 복사합니다. (Java 설치 필요 없음)
2. 그 PC에서 **지금 출석 관리 프로그램을 먼저 실행**합니다. (로그인 화면까지만 떠 있어도 됨)
3. `AttendanceMigrate.exe`를 더블클릭합니다.
4. ① 예전 데이터: DB 비밀번호를 넣고 **옛 데이터 확인**을 누릅니다. 반·학생·출석 개수가 나오면 성공입니다.
   - MariaDB 서비스가 꺼져 있으면 켤지 물어봅니다. (관리자 권한 확인 창이 한 번 뜸)
   - DB 이름이 틀리면 그 PC에 있는 DB 목록을 보여 줍니다.
   - 예전 DB에 계정이 여러 개 있었다면 "옛 계정"에서 옮길 계정을 고릅니다.
5. ② 지금 프로그램: 데이터를 넣을 계정의 아이디·비밀번호를 넣습니다. 계정이 없으면 "새로 만들기"를 체크합니다. (비밀번호 8자 이상)
6. **옮기기 시작** → 끝나면 출석 관리 프로그램에서 새로고침을 누릅니다.

## 동작 방식
- 데스크톱 앱이 띄운 내장 서버의 API(`/api/classes`, `/api/students`, `/api/attendance`)로 넣습니다. 번호(id)는 새로 매겨집니다.
- 여러 번 실행해도 중복되지 않습니다. 이미 있는 데이터는 다음 기준으로 판단합니다.
  - 같은 이름의 반
  - 같은 반에 있는 같은 이름의 학생
  - 같은 학생의 같은 날짜 출석
- 이미 있는 출석 기록은 **덮어쓰지 않습니다**. 지금 프로그램에서 입력한 기록이 우선입니다.
- 소속 반이 없는 학생, 학생이 없는 출석, 알 수 없는 출석 상태는 건너뛰고 기록에 남깁니다.
- 실행 기록은 `%USERPROFILE%\.attendance-desktop\migrate-log-날짜.txt`에 저장됩니다.
- 정식판(BETA=false)의 DEMO 계정에는 데모 제한(반 1개·학생 3명·이번 달)이 걸리므로, 라이선스를 등록한 계정에 옮겨야 합니다.

## 만들기
`powershell -ExecutionPolicy Bypass -File build_migrate.ps1` → `dist_tools\AttendanceMigrate.exe`(단일 파일)와 `dist_tools\AttendanceMigrate\`(폴더판)
소스: `migrate\src\migrate\`
